LEAK

Your logs are shipping your customers' data.

LogLeak proves it, has IBM Bob fix it, then proves the fix. It runs your app's own tests, watches every log line, print() and traceback, and traces each leaked email, phone number, card, CNIC, IBAN or token to the exact file:line that wrote it.

How it works
1 · SEED

Canary PII

Fake but valid data (a Luhn-valid card, a .test email) is injected into the tests, so any match in a log is a confirmed leak, not a guess.

2 · CAPTURE

Runtime, not static

A pytest plugin hooks logging and stdout, catching leaks through __repr__, f-strings, tracebacks and third-party libraries that grep can't see.

3 · FIX

IBM Bob repairs it

Bob gets a masked report and fixes each leak at its source. Bob never sees raw PII, so the fixer never becomes a new leak.

4 · VERIFY

Anti-cheat gate

The same flows run again. The gate passes only with zero leaks, passing tests, and logs that still keep their useful IDs, so deleting logs doesn't count as a fix.
