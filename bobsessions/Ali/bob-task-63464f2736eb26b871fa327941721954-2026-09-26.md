### How it works

`cmd_watch` opens the log source, then runs the existing [`detect()`](logleak/detectors.py:245) engine on **every new line as it arrives** — no buffering delay. The moment a PII finding is seen, [`_alert()`](logleak/cli.py:224) prints a colour-coded breach notice to stderr with the masked value and masked context line, then continues watching.

**Two modes:**

```bash
# Tail a running app log file (seeks to EOF on open, then polls every 0.2 s)
logleak watch /var/log/caredesk/app.log

# Pipe stdout/stderr directly (zero-latency, great for: myapp 2>&1 | logleak watch -)
python caredesk/app.py 2>&1 | logleak watch -
```

**Flags:**

| Flag | Effect |
|---|---|
| `--canaries-only` | Suppress suspected findings; only fire on confirmed canary matches |
| `--poll 0.5` | Change the file-tail polling interval (default 0.2 s) |

**Exit codes:** `0` if no breaches were detected when Ctrl-C is pressed; `1` if at least one breach fired — useful for CI/CD integration.

**All 75 non-e2e tests pass.** No new dependencies — only stdlib [`time`](logleak/cli.py:7).

### Usage

**Pipe a running app through stdin (zero-config deployment):**
```bash
uvicorn caredesk.app:app 2>&1 | logleak watch - \
  --smtp-host smtp.gmail.com \
  --smtp-user alerts@mycompany.com \
  --smtp-password "app-password" \
  --smtp-to security@mycompany.com \
  --smtp-to oncall@mycompany.com
```

**Tail a log file:**
```bash
logleak watch /var/log/caredesk/app.log \
  --smtp-host smtp.sendgrid.net --smtp-port 587 \
  --smtp-user apikey --smtp-password "$SENDGRID_KEY" \
  --smtp-to security@mycompany.com \
  --smtp-app-name "CareDesk Production"
```

**Programmatic — in your app's `logging_config.py`:**
```python
from logleak.watch_handler import install_watch_handler
from logleak.notifier import SmtpConfig

install_watch_handler(
    smtp=SmtpConfig(
        host="smtp.gmail.com", port=587, use_tls=True,
        username="alerts@mycompany.com", password="app-password",
        to_addrs=["security@mycompany.com"],
    )
)
```

**Flood protection:** `--smtp-cooldown 300` (default 5 min) — if the same `file:line:kind` fires repeatedly, only the first email is sent per cooldown window. Console alerts still show every hit.

## How LogLeak Live Watch Works — End to End

### The detection pipeline

When your app runs, every call to `logger.info(...)`, `logger.debug(...)`, `logger.exception(...)`, etc. goes through Python's standard logging machinery. `install_watch_handler()` adds [`LeakWatchHandler`](logleak/watch_handler.py:95) as one more handler on the **root logger** — meaning it sees every record from every logger in the entire process, including third-party libraries.

```
Your code calls:  logger.info("Patient registered: %s", patient)
                          │
                          ▼
            Python logging.Handler chain
                ┌─────────────────────┐
                │  StreamHandler      │  ← writes to stdout/file as normal
                ├─────────────────────┤
                │  LeakWatchHandler   │  ← LogLeak's observer (read-only)
                └─────────────────────┘
                          │
                    record.getMessage()
                    fully formats the string:
                    "Patient registered: Patient(email=canary.patient@logleak.test ...)"
                          │
                    detect(message, canaries)
                          │
                  ┌───────┴────────┐
                  │  Finding found │
                  └───────┬────────┘
                          │
                    mask() each value
                          │
                    BreachEvent built
                    (only masked fields)
                          │
                  ┌───────┴──────────────────┐
                  │                          │
            _default_on_breach()       EmailNotifier.__call__()
            prints to stderr            checks cooldown → sends SMTP
```

The handler **never modifies the record and never drops it**. The app's logs are written exactly as before. LogLeak is purely observing.

---

### What `record.getMessage()` catches that grep misses

The critical step is calling `record.getMessage()` before scanning. This fully applies `%`-style formatting:

```python
# Your code writes this:
logger.debug("Charging card %s for patient %s", card_number, patient_id)

# record.msg  = "Charging card %s for patient %s"   ← what grep sees
# record.args = (card_number, patient_id)
# record.getMessage() = "Charging card 4242424242424242 for patient P-001"
                                          ↑
                                  LeakWatchHandler scans THIS
```

Static scanners and log file parsers see the format string. LogLeak sees what was actually written.

### The three deployment modes explained

#### Mode 1 — Pipe (zero code changes)

```
uvicorn myapp:app 2>&1 | logleak watch -
```

```
Process tree:

  bash
  ├── uvicorn (your app)         writes to stdout/stderr
  │                                     │
  └── logleak watch -            reads stdin line by line
                                        │
                                  detect() on each line
                                        │
                                  breach → alert + email
```

**How the line gets there:** uvicorn writes a log line to its stdout. The shell pipe (`|`) connects that stdout directly to `logleak watch -`'s stdin. Every line is processed the moment the newline character arrives — there is no file, no disk write, no polling delay. The latency is the time for one `detect()` call, typically under 1 millisecond.

**Limitation:** you are scanning the already-formatted string as written to the terminal, which includes the timestamp and level prefix from the formatter. The detector still finds PII inside it, but the `pathname` and `lineno` in the `BreachEvent` will be the log file path (`-`) with line 0, not the actual source file, because there is no way to recover that from a formatted string.

#### Mode 2 — File tail

```
logleak watch /var/log/myapp/app.log
```

```
  logleak watch (your terminal / service)
       │
       │  open(log_path)
       │  fh.seek(0, 2)   ← jump to END of file on startup
       │                    (does not replay old logs)
       │
       └── loop:
             raw_line = fh.readline()
             if raw_line:
                 detect(raw_line)          ← immediate
             else:
                 time.sleep(0.2)           ← poll interval
```

**Why `seek(0, 2)` matters:** without it, every startup would re-scan thousands of historical log lines and send email storms. By seeking to end first, watch only ever sees lines written after it started.

**Polling:** the 0.2s default means a breach is reported within 200ms of the line being written. With `--poll 0.05` that drops to 50ms. There is a natural trade-off: lower poll = more CPU; higher poll = more latency.

#### Mode 3 — In-process handler (recommended)

```python
install_watch_handler(smtp=SmtpConfig(...))
```

```
  Your process memory:

  root logger
    handlers:
      ├── StreamHandler        (writes to stdout)
      └── LeakWatchHandler     (scans every record)
                │
                │  emit(record) called synchronously
                │  inside the same thread that called logger.info()
                │
                ▼
            detect(record.getMessage())
                │
            breach found?
                │
            EmailNotifier.__call__(event)
                │
            cooldown check (thread-safe dict + lock)
                │
            smtplib.SMTP(host, port)   ← blocking SMTP call
            starttls() → login() → sendmail()
```

**Important:** the SMTP call is **synchronous and blocking** in the thread that emitted the log record. For a low-volume breach this is fine — it happens once per cooldown window. If you are in a high-throughput async context (e.g. FastAPI with uvicorn), you should either keep the cooldown high (default 300s is reasonable) or replace the email callback with one that pushes to a queue and sends in a background thread. The console alert always runs synchronously regardless.

### How the email is built and sent

#### Step 1 — `BreachEvent` is constructed

Inside [`LeakWatchHandler.emit()`](logleak/watch_handler.py:113), after a finding is confirmed:

```python
event = BreachEvent(
    kind="card",
    severity="critical",
    confidence="confirmed",
    masked_value="************4242",   # mask() applied — raw value discarded
    logger_name="caredesk.payments",
    level="DEBUG",
    masked_line="Charging card ************4242 for patient P-001",
    pathname="/opt/myapp/caredesk/payments.py",
    lineno=25,
)
```

The raw value (`4242424242424242`) is used only to produce `masked_value` and is never stored anywhere.

#### Step 2 — Cooldown check

[`EmailNotifier.__call__()`](logleak/notifier.py:193) computes a deduplication key:

```python
key = "caredesk/payments.py:25:card"
now = time.monotonic()   # wall-clock, not affected by system clock changes

with self._lock:          # thread-safe
    last = self._sent.get(key, 0.0)
    if now - last < 300.0:
        return            # suppressed — console alert already fired
    self._sent[key] = now
```

This means: the first breach at this exact location sends an email. The next 299 seconds of hits from the same line do not. The 300th second resets and a new email is sent if another hit arrives.

#### Step 3 — Email is built

[`build_breach_email()`](logleak/notifier.py:55) returns three things:

```
subject = "[CareDesk Production] PII BREACH · CRITICAL · card in payments.py"

plain   = multiline text for clients that block HTML

html    = full self-contained HTML with:
          - red header bar (critical) / amber (high)
          - severity badge
          - detail table: severity / kind / confidence /
            masked value / logger:level / masked message / source
          - footer note: "No raw personal data was included"
```

#### Step 4 — SMTP transmission

```python
with smtplib.SMTP("smtp.gmail.com", 587, timeout=15) as s:
    s.ehlo()
    s.starttls()    # upgrades to TLS — credentials never sent in plain text
    s.ehlo()
    s.login("alerts@example.com", "app-password")
    s.sendmail(
        from_addr,
        ["security@example.com", "oncall@example.com"],
        msg.as_bytes(),    # MIME multipart: plain + html parts
    )
```

If the SMTP call fails for any reason (wrong credentials, network timeout, provider down), the exception is caught and a warning is printed to stderr. **The application never crashes or slows down** because of a failed email send.

### Setting up the email in practice

#### Gmail (most common for small teams)

1. Go to **Google Account → Security → 2-Step Verification** — must be enabled
2. Go to **App passwords** → create one labelled "LogLeak"
3. Use the 16-character app password as `--smtp-password`

```bash
logleak watch /var/log/app.log \
  --smtp-host smtp.gmail.com \
  --smtp-port 587 \
  --smtp-user you@gmail.com \
  --smtp-password "abcd efgh ijkl mnop" \   # app password, spaces are fine
  --smtp-to security@yourcompany.com
```

> **Why not your regular password:** Gmail blocks regular passwords for SMTP since 2022. App passwords are scoped solely to SMTP and can be revoked independently.

#### SendGrid (production / high volume)

1. Create a **SendGrid account** → Settings → API Keys → Create API Key (Mail Send only)
2. Verify a sender identity (your from address)

```bash
logleak watch /var/log/app.log \
  --smtp-host smtp.sendgrid.net \
  --smtp-port 587 \
  --smtp-user apikey \              # literally the string "apikey"
  --smtp-password "$SENDGRID_KEY" \ # the actual key starts with SG.
  --smtp-from alerts@yourcompany.com \
  --smtp-to security@yourcompany.com
```

#### AWS SES (enterprise)

1. **SES Console → Verified identities** — verify your from domain
2. **IAM → Create user** → attach `AmazonSESFullAccess` → generate SMTP credentials (these are different from regular AWS keys — generate them in the SES console, not IAM)

```bash
logleak watch /var/log/app.log \
  --smtp-host email-smtp.us-east-1.amazonaws.com \
  --smtp-port 587 \
  --smtp-user AKIAIOSFODNN7EXAMPLE \      # SES SMTP username
  --smtp-password "wJalrXUtnFEMI/..." \  # SES SMTP password
  --smtp-from alerts@yourcompany.com \
```

```python
# myapp/logging_config.py
import logging, os, sys
from logleak.watch_handler import install_watch_handler
from logleak.notifier import SmtpConfig

def configure_logging():
    root = logging.getLogger()
    root.setLevel(logging.DEBUG)
    if not root.handlers:
        h = logging.StreamHandler(sys.stdout)
        h.setFormatter(logging.Formatter(
            "%(asctime)s %(levelname)-8s %(name)s  %(message)s"
        ))
        root.addHandler(h)

    if os.getenv("LOGLEAK_SMTP_HOST"):
        install_watch_handler(
            smtp=SmtpConfig(
                host=os.environ["LOGLEAK_SMTP_HOST"],
                port=int(os.getenv("LOGLEAK_SMTP_PORT", "587")),

                password=os.environ["LOGLEAK_SMTP_PASS"],
                to_addrs=os.environ["LOGLEAK_ALERT_TO"].split(","),

            app_name=os.getenv("LOGLEAK_APP_NAME", "MyApp"),
```
