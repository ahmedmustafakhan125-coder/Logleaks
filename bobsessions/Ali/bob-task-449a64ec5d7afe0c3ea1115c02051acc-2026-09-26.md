# How to Run LogLeak — Complete Guide

## Prerequisites

- **Python 3.11+** — check with `python --version`
- **IBM Bob** installed and on your PATH (required for the automated `logleak fix` step; optional if you use the IDE fallback)
- All commands are run from the **repo root**: `c:\Ali\Personal Projects\Logleaks`

---

## Step 1 — Create and activate a virtual environment

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

After activation your prompt will show `(.venv)`. On macOS/Linux the activation line is `source .venv/bin/activate` instead.

---

## Step 2 — Install the package

```powershell
pip install -e ".[dev]"
```

This installs the [`logleak`](logleak/) package in **editable mode**, meaning changes to `logleak/*.py` take effect immediately without reinstalling. The `[dev]` extra adds `pytest>=8`. It also registers the `logleak` CLI entry point defined in [`pyproject.toml`](pyproject.toml:19) and the pytest plugin entry point at [`logleak.pytest_plugin`](logleak/pytest_plugin.py).

---

## Step 3 — Run the spec tests (confidence check)

```powershell
pytest tests -q -m "not e2e"
```

This runs all **unit/spec tests** (currently 86 of them) in under a second. End-to-end tests are excluded with `-m "not e2e"` because they require spawning subprocesses against the demo app. All should pass before you do anything else. If any fail, something is wrong with the environment — do not proceed.

---

## Step 4 — Scan the demo app

```powershell
logleak scan demo/caredesk
```

**What this does internally** ([`cli.py:cmd_scan()`](logleak/cli.py:65), [`scanner.py:scan_target()`](logleak/scanner.py:17)):

1. Resolves `demo/caredesk` to an absolute path.
2. Creates a temp directory for the raw capture file (`capture.jsonl`).
3. Spawns a subprocess running `python -m pytest --tb=short -q --no-header` inside `demo/caredesk`, with:
   - The `logleak.pytest_plugin` loaded via `-p` (injected automatically since the package registers a pytest11 entry point).
   - `LOGLEAK_OUT` env variable pointing to the JSONL capture file.
   - `PYTHONPATH` set so the target's own package (`caredesk`) is importable.
4. The plugin attaches a [`LeakCaptureHandler`](logleak/capture.py) to the root logger and tees stdout, recording every log line, `print()`, and exception traceback as `CapturedRecord` objects to the JSONL file, along with the exact `file:line` source.
5. After pytest exits, the JSONL is read back and each record is passed through [`detectors.detect()`](logleak/detectors.py) — checking for email, card number (Luhn-validated), CNIC, phone, IBAN (mod-97 validated), JWT, and secret patterns — against the 7 canary values from [`canaries.py`](logleak/canaries.py).
6. Matches are grouped by `(file, line, kind)` into [`Leak`](logleak/tracer.py) objects by [`tracer.trace()`](logleak/tracer.py).
7. [`sitemap.find_log_sites()`](logleak/sitemap.py) walks the AST of every `.py` file in the target to count all log/print call sites.
8. A masked [`Report`](logleak/report.py) is built — **raw PII values never leave this stage**.
9. Three files are written to `runs/`:
   - `runs/report.json` — machine-readable report (all values masked)
   - `runs/report_before.json` — same content, used as the "before" baseline for the gate
   - `runs/leak-report.md` — human/Bob-readable report with masked samples **plus ±5 lines of source context** per leak

The terminal output will show a table like:

```
============================================================
  7 leak(s) found in caredesk
============================================================

SEV       KIND     FILE:LINE                                  SINK       HITS  SAMPLE
----------------------------------------------------------------------------------------------------
critical  card     caredesk/payments.py:25                    log        1     ...card ************4242...
...
```

## Step 5 — Prepare the workspace (and optionally invoke Bob)

### Option A — Prepare only (then fix manually in the Bob IDE)

```powershell
logleak fix demo/caredesk --prepare-only
```

**What this does** ([`fixer.py:prepare_workspace()`](logleak/fixer.py:36)):

1. Copies `demo/caredesk` → `runs/workspace/caredesk`, skipping `__pycache__`, `.pytest_cache`, `.git`, etc. The original `demo/caredesk` is **never touched**.
2. Reads `runs/report_before.json` and regenerates `runs/leak-report.md` with source code context rendered from the workspace copy.
3. Prints the workspace path and exits.

You then open the **Bob IDE**, switch to the **`logleak-fixer`** mode, attach `runs/leak-report.md` to the conversation, and prompt Bob to fix the leaks. Bob's write scope is constrained to `runs/workspace/` by the mode rules.

### Option B — Fully automated (Bob Shell, requires `bob` on PATH)

```powershell
logleak fix demo/caredesk
```

After preparing the workspace, [`fixer.py:run_bob()`](logleak/fixer.py:75) calls Bob Shell non-interactively:

```
bob --chat-mode=logleak-fixer --yolo -p "Fix every leak in @runs/leak-report.md ..."
```

`--yolo` authorises Bob to write files without asking per-edit. Bob uses the **MCP server** (`logleak/mcp_server.py`) — configured via [`.bob/mcp.json`](.bob/mcp.json) — to call tools like `verify_fix` to check its own work and iterate up to 3 rounds until the gate passes. Bob's stdout is streamed live to your terminal.

---

## Step 6 — Verify the fix

```powershell
logleak verify runs/workspace/caredesk
```

**What this does** ([`cli.py:cmd_verify()`](logleak/cli.py:159), [`verify.py:run_gate()`](logleak/verify.py)):

1. Runs [`scan_target()`](logleak/scanner.py:17) on the workspace — the same pytest+plugin flow as `logleak scan`, but on the fixed copy.
2. Loads `runs/report_before.json` as the "before" baseline.
3. Runs all **6 gate checks**:

| Check | What it verifies |
|---|---|
| **G1** `no_confirmed_leaks` | Zero canary-matched leaks remain in the workspace logs |
| **G2** `no_critical_suspected` | No suspected critical PII (non-canary patterns) remain |
| **G3** `tests_pass` | The app's own pytest suite still returns exit code 0 (Bob didn't break anything) |
| **G4** `no_over_redaction` | Useful non-PII tokens (order IDs, appointment IDs) are still present in logs |
| **G5** `logs_retained` | At least 90% of the original log sites are still firing (Bob didn't just delete log lines) |
| **G6** `safety_net` | The app's logging setup has a `RedactionFilter` installed that masks canary values in-flight |

4. Writes `runs/gate.json` and prints a pass/fail per check.
5. Exits with code `0` (all pass) or `1` (any fail).

Expected output after a clean fix:

```
  [PASS]  G1  No confirmed leaks remaining
  [PASS]  G2  No critical suspected leaks
  [PASS]  G3  App tests pass
  [PASS]  G4  No over-redaction (useful IDs present)
  [PASS]  G5  Log site retention >= 90%
  [PASS]  G6  Safety-net RedactionFilter active

  [GATE PASSED]
```

## Step 7 — Start the dashboard

```powershell
logleak serve
```

Opens a **FastAPI + vanilla JS dashboard** at `http://127.0.0.1:8765/ui/`. It reads the `runs/` files (reports, gate result, diff) and renders:
- Before/after log streams with PII highlighted
- The leak table with source context
- The gate panel with per-check status
- A diff view between `demo/caredesk` and the fixed workspace

You can pass `--host` and `--port` to change the bind address:

```powershell
logleak serve --port 9000
```

## Full command sequence at a glance

```powershell
# Once, after cloning:
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# Every run:
pytest tests -q -m "not e2e"           # sanity check — all 86 should pass
logleak scan demo/caredesk             # detect leaks → runs/report*.json + leak-report.md
logleak fix demo/caredesk --prepare-only  # copy workspace (then fix in Bob IDE)
# — OR —
logleak fix demo/caredesk              # automated Bob Shell fix
logleak verify runs/workspace/caredesk # run 6-check gate
logleak serve                          # dashboard at http://127.0.0.1:8765/ui/
```

## Key files produced in `runs/`

| File | Produced by | Contents |
|---|---|---|
| `runs/report.json` | `logleak scan` | Masked scan report (before) |
| `runs/report_before.json` | `logleak scan` | Same — kept as the gate's before-baseline |
| `runs/leak-report.md` | `logleak scan` / `logleak fix` | Human-readable masked report with ±5 lines source context per leak |
| `runs/workspace/caredesk/` | `logleak fix` | Working copy that Bob edits — original is never touched |
| `runs/report_after.json` | `logleak verify` | Masked scan report (after fix) |
| `runs/gate.json` | `logleak verify` | Gate result: 6 boolean checks + reasons |

All files under `runs/` are gitignored. Raw capture JSONL files (containing unmasked PII values during the scan phase) stay entirely local and are never read back by any tool after [`scanner.py`](logleak/scanner.py) processes them.
